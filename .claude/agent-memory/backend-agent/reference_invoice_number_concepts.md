---
name: Two distinct invoice number concepts coexist
description: feeCollectionSessions.invoiceNumber (timestamp-based, legacy) and invoices.invoiceNumber (INV-YYYY-NNN, formal) are unrelated — do not conflate them
type: reference
---

The schema has two separate "invoice number" concepts. They are not interchangeable:

1. **`feeCollectionSessions.invoiceNumber`** — generated by `lib/feeCollectionUtils.ts#generateInvoiceNumber(timestamp)`, format `INV-{timestamp}`. Created when payment is collected. Indexed via `by_invoice`. This is essentially a receipt/transaction reference.

2. **`invoices.invoiceNumber`** — generated by `lib/invoiceUtils.ts#formatInvoiceNumber(yearLabel, seq)`, format `INV-YYYY-NNN` with sequential numbering per academic year. Created when an invoice is generated (issue #24+). Indexed via `by_invoice_number`. This is the formal billing document number.

**Why:** They came from different features at different times. The collection-session number predates the formal invoicing feature.

**How to apply:** When a task says "invoice number", clarify which one. Generation logic, indexes, and validation rules are different. The formal invoice numbering scans `invoices.by_year` for the current max sequence; the session numbering is timestamp-only and never collides by construction.
